# ECOAGENT 0.19.1 — institutional diagnostics and controlled release updates
The existing tool names are unchanged. Read returns explicit HTTP outcomes and public visible field metadata, never field values. Redirects are blocked, including same-origin redirects, rather than followed; some pages may become unavailable. No login, clicks, uploads or submission. This is not a network egress firewall.
## Release updater (Windows, pilot)
scripts/auto-update.ps1 defaults to checking the latest stable GitHub Release, not main. It requires a version tag, main ancestry and a successful verification workflow for that exact revision. No release means no update. -Apply explicitly enables installation for one run. -InstallSchedule -Apply registers a daily limited, interactive-user scheduled task, default 03:00; choose an idle maintenance window. It will not run when that Windows user is logged out. No remote MCP update or shell tool is exposed.
scripts/install-release.ps1 wraps the pinned updater, backups tracked targeted source, tests both drives, restarts the existing alias and attempts restoration if a failure occurs. Power loss/failed restoration requires manual recovery from retained backup/journal. Do not use during an active application or browser job. The scheduler cannot yet detect in-flight requests. Test on the actual computer before enabling the schedule. No signed release trust root is configured; trust is limited to this repo and GitHub/CI, so protect maintainer accounts and release tags. No credentials or local profiles copied. No release is published in this change. Only publish releases after local validation.
