# ECOAGENT Cloud 0.5 preview
Single operator experimental backend. Do not expose for general public use. No persistent sessions, login, or multi-tenant access. Docker build from repository root: docker build -f cloud/Dockerfile -t ecoagent-cloud . . Set distinct random ECOAGENT_OPERATOR_KEY and ECOAGENT_CLIENT_KEY (32+ characters) as server secrets, never in Git. ECOAGENT_ALLOWED_ORIGINS defaults to https://example.org; only explicitly vetted HTTPS origins. Use isolated container networking with outbound firewall denying private, link-local and metadata addresses; browser route allowlist alone is not an SSRF defense. Chromium sandbox must work; do not disable it to deploy. HTTPS reverse proxy required. No browser authentication until private sessions and manual takeover are implemented. Never send secrets in task bodies. Screen only for operator; screenshot may show personal data. Jobs expire after 15 min, browser idle after 5 min. API POST /api/jobs with client Bearer and one operation; operator approves on dashboard. GET /api/jobs/ID returns shared results only. No direct ChatGPT integration yet; requires supported authenticated connector or client. Hosting may cost money. Deployment and browser tests pending.

## 0.6: batches
POST /api/jobs accepts {"steps":[{"op":"open","url":"https://example.org"},{"op":"inspect"}]} from client or operator. Operator approves the entire visible batch. Up to 12 actions; first error stops execution. Exact label resolution: {"op":"find","label":"Name","action":"fill","value":"Example"}. Duplicate labels fail closed. Approval is for the complete list, not a guarantee of external submission; verify receipts manually. Do not include credentials or sensitive personal data. CI verifies protocol and syntax, not real browsers. Hosting remains pending.
